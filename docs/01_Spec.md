## מודל הנתונים

- **bs_catalog**: רשומה לכל סט (מפתח `set_num` כמו `76388-1`). נמשכת מ Brickset ונשמרת. שדות: מספר, שם, שנה, סדרה, תת סדרה, חלקים, מיניפיגורות, גיל, אריזה, תאריכי השקה ופרישה, מחירי מחירון (US, UK, DE, CA), תמונה, ברקודים EAN ו UPC, מידות, דירוג, תגיות, תיאור באנגלית, תיאור בעברית (נכתב פעם אחת), raw.
- **bs_items**: שורת מלאי. סוג (set, polybag, gear, parts, other), קישור לקטלוג, שם מותאם לפריטים שאינם בקטלוג, מיקום, כמות, מצב (sealed, open, built), סטטוס (sale, personal, hold, sold), מחיר ומקור המחיר, תגיות, הערות, תמונה.
- **bs_zones**: אזורים (קיר, ארון, חדר, מחסן): קוד קצר (`B`), שם, צבע (red, blue, green, yellow, cocoa, oak, ink, stone), site (איפה: "חדר הלגו", "מחסן"), סדר. הצבע של האזור הוא הצבע של כל הפריטים שבו בכל המסכים.
- **bs_locations**: מדפים, קופסאות, ארונות, מגירות, תאים (`kind`), קוד מלא `B3` = אזור + מספר, תיאור חופשי, `active` (מדף מושבת לא מוצע בהוספה). נוצרים ומנוהלים ממסך ההגדרות.
- **bs_movements**: כל שינוי כמות (הוספה, מכירה, העברה, תיקון).
- **bs_settings**: מקדם ישראלי, שער דולר, מע"מ.
- **bs_secrets**: מפתחות API. RLS בלי מדיניות, קריאה רק דרך service role.
- **bs_owners**: מי מורשה. כל המדיניות (RLS) בודקת `bs_is_owner()`. טריגר על `auth.users` רושם אוטומטית כבעלים את מי שנרשם עם `mar.gilad@gmail.com`.
- **bs_inventory** (view): פריטים עם נתוני הקטלוג והאזור, כולל `retired` מחושב. זה מה שהרשימה והטבלה קוראות.

## זרימות

**הוספה מול המדף (טלפון):** בוחרים מדף פעם אחת → מקלידים 5 ספרות או סורקים ברקוד → פונקציית `lookup` מחזירה את הסט (מהקטלוג המקומי, ואם אין, מ Brickset ושומרת) → כרטיס לאישור עם מחיר מוצע → כמות, מצב, סטטוס (ברירות מחדל: 1, חדש סגור, למכירה) → "הוסף" → שורה ב bs_items ותנועה ב bs_movements. ערימה זהה = שורה אחת עם כמות.

**פריט שאינו בקטלוג** (קלמר, מחזיק מפתחות): הסריקה לא מוצאת → טופס קצר: שם, סוג, כמות, תמונה מהמצלמה.

**רשימה וטבלה:** חיפוש חופשי (שם, מספר, ברקוד, סדרה, מדף), סינון לפי סטטוס, מצב ייצור, כמות, נושא, קיר, תגיות. מיון בכל עמודה. לחיצה פותחת מגירה עם כל הפרטים והשדות לעריכה.

**מכירה:** "סמן כנמכר" מוריד כמות ורושם תנועה. כשהכמות אפס הפריט נעלם מהחנות לבד.

## הארכיטקטורה

- **Supabase** (Postgres, Auth, Storage, Edge Functions). אזור eu-central-1.
- **Edge Function `lookup`**: קלט `q` (מספר סט או ברקוד). סדר: קטלוג מקומי → Brickset getSets (setNumber) → שמירה. ברקוד שלא נמצא מקומית: חיפוש ב Brickset אינו נתמך, לכן הקטלוג מסונכרן מראש.
- **Edge Function `sync-catalog`**: מושכת מ Brickset את כל הסטים של שנה נתונה (עד 500 לעמוד) ושומרת בקטלוג, כולל ברקודים. הרצה חד פעמית לשנים 2012 עד 2026 (כ 40 קריאות, בתוך מכסת 100 ליום), ואחר כך `updatedSince` לרענון.
- **אפליקציה**: Vite + React + TypeScript, עברית RTL, PWA (מתקינה את עצמה בטלפון, עובדת בלי רשת ושולחת כשיש). סורק ברקוד: `BarcodeDetector` המובנה של הדפדפן כשקיים (אנדרואיד כרום), אחרת `@zxing/browser`. בחירת העדשה האחורית הראשית, מיקוד רציף, זום, החלפת עדשה. ספריית לקוח: `@supabase/supabase-js`.
- **אירוח**: GitHub Pages דרך GitHub Actions. כל דחיפה ל main עולה לאוויר.
- **אבטחה**: כניסה באימייל וסיסמה (משתמש אחד). הרשמה ראשונה מאומתת בקוד של 6 ספרות במייל (כך מוגדר הפרויקט tripaloo). RLS על כל הטבלאות. בדפדפן רק המפתח הציבורי (publishable) של Supabase. מפתחות Brickset ו Rebrickable מוזנים ממסך ההגדרות לטבלה `bs_secrets` שרק השרת קורא.
